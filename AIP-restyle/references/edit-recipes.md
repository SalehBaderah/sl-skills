# AIP edit recipes

Read the identity reference first. These are application recipes, not additional official brand mandates. Preserve the original medium; logo placement is a separate step using the exact asset.

## Shared specification

```text
Target: [exact target file/image]; references: [palette/example pages, style only].
Preserve: [subject/count, identity, pose, silhouette, components, composition,
exact copy/language, data, semantic colors, dimensions, aspect ratio, alpha].
Medium: [source]; strength: [subtle/balanced/bold]; theme: [source/light/dark].
AIP palette: #020624 #0F1543 #2F2447 #4A3B68 #58709C #B7CDDD #D4DAFA #F6F9FC.
Apply to [specific designed surfaces and supporting elements].
Keep [natural skin/fur/materials/meaning-bearing colors] accurate.
Shape/texture: [medium-specific constraints]. Background: [treatment].
Logo: integrate the bundled emblem on [requested surface/native branding area],
in [contrasting AIP color] at a clearly visible size. No standalone footer.
Workflow: [exact native/composited master OR supplied-reference raster mockup].
Do not invent logos, wordmarks, new text, borders, objects, or watermarks.
Output: [dimensions, format, alpha].
```

## Pixel art and sprites

First distinguish true grid-based pixel art from a high-resolution pixel-styled illustration. Preserve intentional source shading/texture unless the user requests flat sprites; do not force a style change just because a silhouette has square steps. For strict pixel art, preserve the grid, stepped silhouette, clusters, expression, pose, and meaningful details. Use discrete AIP fills: dark purple shadows, mid purple body, pale lavender highlights, navy details, off-white contrast. Do not introduce smooth gradients, soft shadows, painterly texture, rounded pixel corners, or antialiasing. Requested scaling uses integer nearest-neighbor. Do not silently upscale and call it pixel-perfect.

For a coffee/laptop character, keep closed smiling eyes, mug handle, steam blocks, feet, and laptop angle; keep coffee recognizable. If an on-object logo is requested, use a suitable existing surface without obscuring semantic details; do not silently substitute a footer. Keep exact logo geometry rather than inventing a pixelated approximation. If strict pixel-grid requirements conflict with logo fidelity/size, explain the constraint. Inspect at normal size and high zoom. If the generator cannot preserve the grid, disclose that limitation or use native pixel editing only when authorized.

## Flat icons, vectors, illustrations, and line art

Preserve semantic silhouette, holes, stroke character, optical size, and orientation. Use coherent navy/purple foregrounds and pale accents. Round contours only when compatible. Native SVG retains viewBox, path structure, alpha, and accessibility labels with exact color tokens. Keep icon sets consistent and brand the sheet rather than every UI glyph. Do not add unrequested sticker cutlines.

## Photograph, portrait, product shot, and meme

Preserve identity, natural skin/fur, expression, pose, scene geometry, and important objects. Apply AIP through background, designed surfaces, props, typography, or controlled lighting while retaining photographic materials. Do not reconstruct a subject or polish away intentional low-fi meme character. Keep headlines exact. Compare facial/object geometry with the source.

## 3D objects and clay-style icons

Keep geometry, camera angle, silhouette, depth, roughness, and light direction. Translate designed surfaces into navy/purple with pale accents and readable separation. Preserve believable highlights/shadows rather than forcing every pixel to a hex. Do not make every object glossy. For an on-object logo, use an exact native mockup/UV workflow or a supplied-reference generative mockup with an honest fidelity description. Do not satisfy an on-object request by placing the logo beside it. Keep natural fur/skin, and use AIP clothing only when requested or already present.

## Poster, social design, invitation, cover, banner, and packaging

Preserve hierarchy, content, reading order, focal point, and existing marks that must remain. Reassign background, headline, dividers, and accents using AIP. Keep dark/pale contrast, generous space, and optional restrained motifs. Preserve panel geometry, dielines, safe areas, bleed, and supplied dimensions. Add the emblem in an empty margin. Do not invent event details or claim print-ready CMYK from an RGB preview.

## Slides, documents, and text-heavy layouts

Preserve every page/slide, exact copy, Arabic shaping/RTL, tables, references, numbers, and reading order. Theme masters, headings, charts, and accents consistently. Use Gilroy and Droid Arabic Naskh when authorized files are available; name actual substitutes for previews. Prefer native text/logo layers. Generate supporting illustration separately from long exact text. A rendered slide image is not an editable deck.

## Charts, dashboards, maps, and infographics

Preserve data, axes, scales, labels, legends, ordering, geography, and factual relationships. Use distinct AIP values plus labels/patterns; do not collapse all categories into one purple. Preserve warning/error/safety colors if remapping would mislead. Check text contrast (4.5:1 normal, 3:1 large text as accessibility targets) and meaningful graphical contrast; these usability targets are not brand-guide claims.

## Website/UI/app designs

For screenshot deliverables, restyle the screenshot without implying a working app exists. For explicitly requested code edits, update native tokens/components while preserving interactions, content, states, focus visibility, responsive layout, and accessibility. Place the SVG once in an appropriate branding area, not inside functional controls. Follow applicable website-building skills when building a site; this identity skill supplies styling, not deployment authorization.

## Stickers and transparent assets

Keep subjects compact/readable and use a cutline only when requested or original. Preserve real alpha and clean edges. Keep the emblem clear of subject/cutline; under `auto`, omit it on tiny functional assets if illegible. Transparent output still needs an intended background for logo contrast.

## Mixed media and batches

Treat each layer in its medium: photo stays photo, pixel illustration stays pixelated, native text stays text, logo stays exact artwork. Preserve collage relationships. Decide palette mapping, strength, theme, and logo policy once across a batch. Deliver requested individual assets rather than a replacement contact sheet.

## Motion and unsupported formats

Only claim a complete animation/video/native artifact when tools can produce and inspect it. Preserve timing, motion paths, cross-frame consistency, and readability if supported. Otherwise supply supported stills/specifications and clearly identify the missing export. Do not claim universal format support.
