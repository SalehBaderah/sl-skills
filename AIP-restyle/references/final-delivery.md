# Deliver the actual branded result

The prior workflow could save a correct local composite while the user still saw the image tool's earlier blank-shirt result. A local pixel test alone did not establish visible delivery. This release separates saved-file checks from the host's display step.

1. Identify the final artifact unambiguously: the actual post-compositing file or final image-tool result containing the logo. Keep intermediates separate.
2. Open and inspect that final artifact. At normal full-image scale, verify a conspicuous logo on the requested shirt/object, correct contrast, recognizable emblem, and preserved subject/copy. Inspect a close-up for clipping and geometry too.
3. If compositing, compare the final file with its immediate base: logo pixels must change within the intended surface, dimensions/alpha must be preserved unless explicitly changed, and protected content must stay intact. A script's `display_verified: false` is intentional: file creation is not user-visible delivery.
4. Display the actual final file through the host's supported local-image/file mechanism and provide a real download when supported. Verify the preview transport's MIME type against the actual file bytes: PNG must be served as `image/png`, JPEG as `image/jpeg`. A local viewer may return valid PNG bytes labeled `data:application/octet-stream;base64,...`; that generic MIME can prevent image display. After verifying the file format, use the correct image MIME with the supported renderer, preserving the image bytes. Do not relabel unknown/non-image content or regenerate artwork merely to fix its delivery header. For the image-generation display helper, pass an actual image-generation result; do not wrap a local viewer return as if it were a new image-generation artifact. Do not imply that saving a new PNG changed an older image tool thumbnail.
5. If a host cannot display the composed file, deliver it via its supported file mechanism and clearly identify it. When a visible image-tool mockup is useful, send the branded composite plus logo reference to a final image-edit call that visibly retains the logo, then inspect that actual result. Preserve the exact master separately if geometry matters; generative mockups do not prove pixel/path equality.
6. If the final preview still has a blank shirt, missing/tiny logo, incorrect surface, or old source content, correct it before claiming completion. If the host cannot show or deliver the file, state that limitation instead of claiming the user received it.

Examples are [integrated shirt](../assets/examples/integrated-shirt.png) and [laptop detail](../assets/examples/integrated-laptop.png). These are appearance references, never replacements for a user's current edit target. The shirt example is a generative mockup; the logo assets in `assets/logos/` are the canonical exact geometry.
